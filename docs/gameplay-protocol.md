# Shared-world gameplay

The game server owns character records, location, actions, shared entities and rewards. Browser modules decode the player's game files for presentation and send intent over the existing WebSocket.

Indoor transfers record the destination and floor height in the character’s portal state. Collision updates that height as the character walks, and other players in the same instance receive it as the peer’s `y`. The client uses the saved height when rejoining a dungeon with stacked floors. Older saves use the scene’s entry marker as their starting height reference.

Dungeon mechanisms use `dungeon.use {id}` with the authored block coordinates and RDB object offset. The server checks floor, reach, visibility and trigger conditions. `gameEvent {kind:"dungeonState",location,active}` carries the instance’s full set of changed poses. `dungeon.sync` asks for that set after joining. Door and portal collision comes from the same operator data as the rendered scene. See the [dungeon access report](dungeon-access.md) for the quest-marker service and instance lifecycle.

## Server features

Each `server/rpg/<feature>.js` exports `install(ctx)`. The runtime registers features once per server instance. Keep mutable instance state inside `install`.

- `ctx.players` is the existing Map of connected players, keyed by numeric id. Each player has `id, name, x, z, yaw, moving, rpg`. The JSON-serializable `p.rpg` is private persistent character state, including `p.rpg.location`, a string that defaults to `town:Daggerfall/Gothway Garden`.
- Place addresses name a MAPS.BSA record. The first or only record with a region/name keeps `town:<Region>/<Name>`; a later record with the same name is `town:<regionIndex>/<locationIndex>` (for example `town:0/272`, the second Alik'r Djen Lodge). `interior:` and `dungeon:` use the same pair after their prefix. Resolve with `catalog.at(regionIndex, index)`, `catalog.atPixel(x, y)` or `catalog.get(id, hint?)`; take a region name from `regionNameOf()` and canonical spellings from `canonicalAddress()` in `client/gameplay/travel/identity.js`. When MAPS.BSA loads, travel converts a save once with `migratePlaces()`: location, portal, travel, wilderness return, quest places and repair tickets. It then sets `rpg.travel.identity = 1`. Personal discoveries are `rpg.travel.found = {[regionIndex]: sorted locationIndex[]}`. Legacy `discovered` strings remain until they can be converted.
- `ctx.entities` is a Map keyed by string id. Entities have `{id,kind,name,location,x,z,yaw,sprite?,...}`. A sprite reference is `{archive,record}` from local TEXTURE files. Send visible fields only. Each client sees its own location.
- `ctx.onJoin(fn)`, `ctx.onLeave(fn)`, `ctx.onTick(fn)` register synchronous handlers receiving `(player)`, `(player)`, or `(dtSeconds,nowMs)`. `ctx.onAction(verb,fn)` receives `(player,args)` from `{type:"action",verb,args}`. Fail an invalid action with a user-readable Error. All state changes happen synchronously. Each successful action saves all affected players in a single transaction. `ctx.dirty(player)` marks additional affected players or tick changes for persistence. `ctx.now()` is server monotonic milliseconds.
- `ctx.on(name,fn)` and `ctx.emit(name,payload)` are synchronous in-process gameplay events. `ctx.notify(player,{kind,text?,...})` delivers a private event; `ctx.nearby(location,event)` delivers an event to occupants. Features may publish synchronous cross-domain operations on `ctx.services`. Validate before changing state.
- New accounts and returning guests start with compatible defaults via join handlers. Existing movement and chat remain usable. The server sends `{type:"rpg", character, entities, peers, selfId}` to each client on changes. `peers` contains public fields only, including position, id, name, readied weapon and current animation where present. Private events are `{type:"gameEvent",event}`.

## Browser features

On sign-in and reconnect, Play sends `arrival: true` in its join request. A matching welcome keeps the character off other players’ screens and the public map while the client loads. Each RPG snapshot includes `readiness` for its location. The NPC and combat services report when they have placed the occupants, including a confirmed count of zero for an empty place. An outstanding quest placement in this location adds a private readiness entry for the character who owns it. That character waits for the server to publish the person or item before loading its artwork. Play waits for a fresh snapshot, the current scene and collision, the terrain and towns visible from the arrival point, and every sprite archive used by the roster published to that character. This includes people farther away than the drawing distance. After drawing the first playable frame it sends `{type:"arrived"}`. Cancel closes the joining session. A failed required resource opens a recovery screen.

A signed-in Castle Daggerfall fixture delayed the sprite archive for a sorcerer 227 m from the saved character. The public map stayed at zero players while the archive was pending. At the first gameplay frame, all 17 sprite sets for the 149 occupants were ready and the renderer drew the 139 within its 220 m drawing distance.

Each `client/gameplay/<feature>.js` exports `install(api)`. The game shell loads these modules at startup. `api.state` holds the latest RPG message (initially null); `api.files` is the iterable of selected File objects. `api.act(verb,args={})` sends intent. `api.on(name,fn)` subscribes to `assets` (File array), `state` (entire RPG message), `event` (game event), `frame` (camera, dt, now seconds, renderer, town), `screen` (screen name), and `scene` (town/world mesh). `api.emit(name,detail)` publishes browser-only events. Subscribe to `panel` for menu switches, and call `api.openPanel(id)` to open a screen. `api.registerPanel(id,title,render)` registers a functional panel. The shell calls `render(container,api)` on opening and on relevant state changes. `api.message(text)` shows feedback, `api.modalOpen` gates gameplay shortcuts. Use the provided panel container and DOM text nodes. Modules may add scoped styles in `client/gameplay/<feature>.css`.

## Domain fields and actions

- Character owns `rpg.character` with `race, className, attributes, skills, level, health, maxHealth, fatigue, maxFatigue, magicka, maxMagicka`. Skills and attributes are keyed by classic English display name. See [character rules](#character-rules) for the server services and game-time progression.
- Equipment owns `rpg.inventory` (array of `{id,template,name,quantity,slot?,...}`), `rpg.equipment` (slot → item id, including `rightHand`), and `rpg.gold`. Services `ctx.services.giveItem(p,template,quantity=1)` and `ctx.services.takeItem(p,itemId,quantity=1)`. Inventory actions `inventory.equip`, `inventory.unequip`, `inventory.use`, panel `inventory`. Server catalogue includes `iron-longsword` and `gold` is currency.
- Combat owns `rpg.readied` boolean. Actions `combat.ready` with `{ready}`, `combat.attack` with optional `{targetId,direction}`. A defeated player's browser sends `combat.rise` when its death movie ends or is skipped; the server otherwise resurrects after 16.5 s, just past the 15 s movie. Monster states use `kind:"monster",hp,maxHp,sprite,animation`. A player finishing blow on an ordinary enemy emits `kill` with `{player,entity}`. Send `swing` events with `playerId,direction`. Magic may call `ctx.services.damageEntity(p,entity,amount)`. Every EnemyBasics type spawns (monsters 0-38 and 40-42, classes 128-145, City Watch 146). Reserved values (39 Horse_Invalid, 99, and unknown marker values) never spawn a stand-in and are counted in `services.combatStats()`. Monster entities also publish `origin` (`rdb-fixed`, `rdb-random`, `rdb-random-water`, `wod-fixed`, `wod-random-climate`, `climate-random`, `quest`, `demo`), `affinity`, `careerSource`, `hostile:false` for passive markers, and `form:'winged'` once a Daedra Seducer has transformed (`animation` `transform1`/`transform2`). Dungeon encounter sites may carry `waterLevel`, `markerY`, `slot`, `classicSeed`, `passive` and `gender`. Monster spells go through magic's `services.enemyCast(entity, stdIndex, target)`. Player damage from enemy sources goes through `services.hurtPlayerBy`. Other features place real enemies with `services.createEnemy(location,id,x,z,{id,level,gender,origin})`.
- NPCs use `kind:"npc",role`; interaction is `npc.talk` with `{targetId}`. Emit `talk` with `{player,entity}`. Quest records live in `rpg.quests`; panel `journal`. Spells use panel `spellbook`. Travel uses panel `map`. Parties and trades use panel `party`.
- Combat stores the fractional swing fatigue in `rpg.combatFatigue`. It emits an `arrowLaunch` event with a `projectileId`, `location`, position, direction, speed and range. `arrowImpact` carries the same ID and location, with the arrow-tip position and a `reason` of `target`, `wall` or `range`. If the shooter leaves the flight's location and the flight is cancelled, the event carries `reason: "cancelled"` without a position. A private quest foe's shots and shots aimed at that foe go only to its viewers. Private target impacts likewise stay within the foe's audience. [Combat coverage](classic-combat-coverage.md)
- A monster that damages another monster emits `hit` with `attackerId` set to the attacker entity ID and `playerId: null`. `monsterAttack.targetId` is a character ID for attacks on players and an entity ID for attacks on monsters. On an allied finishing blow, `death.killerId` identifies the ally and the summoner's damage contribution qualifies them for the usual `combat.loot` window. Artifact summons use `origin: "sanguine-rose"` or `origin: "skull-of-corruption"`. The same `inventory.use` action handles both artifacts. [Artifact combat and verification](classic-combat-coverage.md#artifact-allies)
- Combat feedback events carry the amounts the server applied, after shields and resistances. `swing {playerId,direction,weapon}` goes to the location. `hit {playerId,entityId,damage,hp,maxHp,source}`, `miss {playerId,entityId}`, `monsterAttack {entityId,targetId,hit,damage,ranged?}` and `death {entityId,name,killerId}` go to everyone who can see the monster. `ineffective {entityId,text}` goes to the attacker only. `hit.backstab: true` marks a blow that received the classic backstab bonus. `monsterAttack.absorbed: true` marks a landed blow that a magical shield soaked completely; it still reports `hit: false, damage: 0`. The injured player alone receives `hurt {damage,cause}` for health lost to anything other than a monster's blow. `cause` is `spell` (enemy or reflected spells), `trap`, `fall`, `drowning`, `condition` (disease, poison and the lycanthrope health limit) or `other` (sunlight, holy ground, cursed items). The player whose health a spell, a potion or a temple's priests restore receives `heal {amount}`. Rest and regeneration send no `heal`.
- Gameplay source references are available in `.ref/daggerfall-unity` and the MIT JS edition in `.ref/dfjs-research-03`. Keep appropriate notices next to adapted code. Load Bethesda art, text and audio from player- or operator-supplied archives. Never include a reference checkout or game archive in the distribution.
- Mount (`server/rpg/mount.js`, `client/gameplay/mount.js`) owns `rpg.mount = {riding, coat}`. General stores stock a `horse` (classic template 94: 1000 gold base, weightless in the pack). Action `mount.ride {on?}` toggles riding. Riding is allowed only with a horse, outdoors (`town:` or `wilderness:`) and while not defeated; dismounting is always allowed. A door, defeat, or losing the horse dismounts the rider at once. `ctx.services.moveSpeed(p)` gives the mounted ground speed and the game loop uses it in place of the 4 m/s walk. That speed is DFU's `(Speed + 375) / (50 + 150)` of the walk, from `client/gameplay/mount/rules.js`, which the browser's prediction shares through `api.moveSpeed`. Collision applies unchanged. Peers carry `mounted: true, coat` while riding. Events `{kind:"mount", playerId, mounted, text}` go to the rider, and `{kind:"mount", playerId, name, mounted}` to others in the location. The browser shows a Ride/Dismount button in the action bar and on the H key, draws the classic first-person horse from `MRED00I0.CFA`, raises the eye 0.8 m, and draws mounted peers on the `TEXTURE.201` horse flat.
- Travel `travel.go {to, options, expectCost?, requestId?}` charges and moves at once. A repeated `requestId` answers again without a second fare. The `travel` event and `rpg.travel.lastTrip` carry `route {from, to}` (map pixel, name, region), `mounted`, `showMs` and `requestId`. The event is `silent`: the browser journey (`client/gameplay/journey.js`) shows the arrival text when it lands. A refused journey sends no event and shows no journey. The browser journey runs in phases: it rises behind the traveller, then shows the bay assembled from the player's own FMAP region maps. The view zooms out from the origin until both ends show, and the character rides the classic stepped route with day progress. Arrival falls back into first person. While it plays, the hooks `api.movementLocked`, `api.viewTransforms` and `api.journeyGate()` hold input, the camera and `api.setScene`. Reduced motion skips the rise, fall and zoom. A reconnect within `showMs` replays the rest of the journey.

## Character rules

The server reads the standard careers, including restrictions and abilities, from the operator’s CLASS*.CFG files. A custom career is rebuilt from its saved design. Progression uses permanent scores. Consumers of live stats call `effectiveAttribute(actor, attribute)` and `skillValue(p, skill)`. These combine the permanent scores with the available magic and condition modifiers. `baseAttribute(actor, attribute)` and `baseSkillValue(p, skill)` read permanent values. The browser gets changed attributes in `character.effectiveAttributes`. Private `rpg` snapshots carry `locomotion` with the live skills, spell flags, encumbrance and traits used by the movement authority.

- `equipmentRestriction(p, item)` and `weaponRestriction(p, skill)` return a refusal message or null. Inventory enforces weapon, material, armor and shield restrictions when equipping, using gear, creating a character and repairing a saved loadout.
- `characterAttackModifiers(p, {skill, group, armed})` returns `{toHit, damage}`. Combat supplies the skill name and the classic opponent group `Animals`, `Daedra`, `Humanoid` or `Undead` when applicable.
- `characterSavingThrow(p, kind)` returns `{immune, critical, modifier}` for immunity, critical weakness and additive saving-throw points. Magic and conditions use lower-case kinds such as `cold`, `disease` or `paralysis`.
- `characterMagery(p)` returns `{blocked, multiplier, absorbs}`. The multiplier applies to maximum magicka. `characterRestRecovery(p)` returns the three hourly resource recoveries. `characterTraversal(p)` provides the climbing and swimming skill bonuses and exertion and jump multipliers.
- `languageCheck(p, skill, {roll, bonus})` returns `{skill, chance, success}` for an eligible language. Combat supplies a roll from 0–199 and the Comprehend Languages bonus, then tallies the encounter. The check uses the effective language skill, Personality and whether the weapon is drawn.
- `characterTraining(p, skill, {max, commit})` returns `{ok, reason, value, max, minutesLeft}`. NPCs check the hall’s membership, tutor catalogue and price. A committed lesson tallies practice, drains fatigue and advances the character’s clock by three hours. Twelve game hours must pass from the start of one lesson to the next. The same cooldown applies at every tutor and survives reconnect.
- `advanceSkill(p, skill, amount)` tallies an activity. Every six game hours, sufficient practice adds one permanent point and consumes its tally. A mastered primary at 100 limits further increases in other skills to 95. Level progression counts all three primaries, the top two majors and the highest minor. Health gains use the career’s roll and permanent Endurance. Temporary modifiers apply to play immediately without raising permanent scores.

The 35 skills are consumed in the following activities.

|---|---|

| Etiquette, Streetwise | Conversation and eligible humanoid pacification |

| Jumping, Swimming, Climbing, Running | Movement, exertion and traversal practice |
| Lockpicking, Pickpocket, Stealth, Mercantile | Locks, theft, detection and trading |
