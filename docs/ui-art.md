# UI art from ARENA2

The game reads original artwork at runtime from the active ARENA2 selection. The folder picker and the loopback-only installed-file route expose the same file interface. The website uses its own static assets and Thomas Cole’s *The Past*. Captures containing installed game art belong in the ignored `progress/screenshots/agents/` directory.

| Screen | Finding and source |
| --- | --- |
| Public site, launcher, loading and recovery | The Cole images, site mark, site map and interface fonts resolve from the static site. The launcher keeps these assets independent of an ARENA2 selection. |
| HUD and panel tabs | The compass ribbon gains `COMPASS.IMG` and `COMPBOX.IMG`, with the text ribbon available while the files are read or when either is missing. Ready, Inventory, Spells, Travel and Rest use their `MAIN00I0.IMG` tiles. Use and Interaction use the grab tile in `MAIN01I0.IMG`. Character shows the current head from `FACE??I0.CIF`. The browser manages Attack as its own control, so it has a text label. |
| Character creation and sheet | Race, gender and face choices and the saved sheet use the matching `FACE0?I0.CIF` or `FACE1?I0.CIF` record with `ART_PAL.COL`. An open panel refreshes as soon as the file set changes and again when the class data finishes reading. All 160 installed faces decode with visible pixels. |
| Conversation, shop and guild | The UI resolves the actor’s sprite through `FLATS.CFG` to a portrait in `TFAC00I0.RCI`. A matching named faction or dedicated named flat in `FACTION.TXT` selects the special face in `FACES.CIF` or the common archive, as appropriate. The source flat itself is a fallback when a portrait record is missing. The debug card in common record 410 is excluded. The installed common and special archives contain 503 and 61 complete records respectively. |
| Spellbook and casting | `ICON00I0.IMG` supplies 69 spell emblems. Target and element indicators come from `MASK04I0.IMG`. The five elemental `*00C6.CIF` files each supply six casting frames. A missing icon leaves the associated text readable. |
| Travel and regions | The overview and hit mask come from `TRAV0I00.IMG` and `TRAV0I01.IMG`. All 51 configured `FMAP*.IMG` region pictures decode against `FMAP_PAL.COL`. The three empty `FMAP0I00.IMG`, `FMAP0I01.IMG` and `FMAP0I16.IMG` files correspond to multipart regions and use their lettered maps. `TRAVDI05.IMG` and `TRAVCI05.IMG` identify the two-part west and east controls. The map art can render while the location catalogue loads. File changes invalidate earlier canvas draws, and the panel rebuilds immediately when reopened. |
| Automap, Wilderness and Places | Automap terrain and markers come from current scene geometry and coordinates. The player arrow reflects current heading, while the door markers identify interactive entrances. The Automap tab and floor-change controls use their tiles in `AMAP00I0.IMG`. The Wilderness and Places views continue to show the data for their current location. |
| Journal | A crop of the original `LGBK00I0.IMG` parchment marks the HUD control, menu tab and Journal title. Journal content and quest actions keep their regular text rendering. |
| Bank and Repairs | The repair panel shows the current smith’s matching portrait when the counter identifies a live NPC. A building counter identifies a service location and has no portrait record. |
| Party & Trade, Settings, Sound, People, Controls and Leave | Multiplayer rosters, browser input and session controls use text. Classic ARENA2 has no matching multiplayer or browser-specific control art. |

The formats and source coordinates follow Daggerfall Unity’s [ImgFile](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/API/ImgFile.cs), [CifRciFile](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/API/CifRciFile.cs), [FlatsFile](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/API/FlatsFile.cs), [TalkManager](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/Game/TalkManager.cs), [HUDLarge](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/Game/UserInterface/HUDLarge.cs), [HUDCompass](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/Game/UserInterface/HUDCompass.cs), [SpellIconCollection](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/Game/UserInterface/SpellIconCollection.cs), [Travel Map](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/Game/UserInterfaceWindows/DaggerfallTravelMapWindow.cs) and [Automap](https://github.com/Interkarma/daggerfall-unity/blob/master/Assets/Scripts/Game/UserInterfaceWindows/DaggerfallAutomapWindow.cs) (MIT, © 2009–2023 Daggerfall Workshop).

## Verification

- Ran `/play.html` at 1160×760 and 412×820 on isolated loopback servers and accounts. Confirmed the file picker with the installed-file endpoint disabled, and separately confirmed automatic loading through the installed-file endpoint. Each source exposed 1,590 files.
- Walked to and opened the Town Crier, Provisioner, Fighters Guild and Mages Guild conversations. The mounted canvases resolved to `FACES.CIF#21`, `TFAC00I0.RCI#445`, `TFAC00I0.RCI#436` and `TFAC00I0.RCI#446` respectively. The Provisioner’s own face stays visible after opening the stock list at both widths.
- Bought and cast Water Breathing through the live spellbook. The browser reported original casting art and drew nontransparent pixels on the first-person overlay. Compared the 320×200 overview, 320×160 regional image and town Automap across panel opens.
- In a browser test harness, temporarily omitted the compass strip and the current regional image while Travel was open. The text compass and an unavailable-map status appeared. Restoring the file selection repainted the compass and region.
- Checked the original floor button crops and the town Automap. A multi-floor interior and the live smith-counter portrait were outside the browser route exercised here.
